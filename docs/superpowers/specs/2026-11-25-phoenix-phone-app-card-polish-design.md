### Tip input and modal policy

Current main hides TutorialCard in both GameHud._open_modal and _reconcile_modal_presentation. Existing integration tests explicitly require that Settings/shop hide it; the ticket also requires dismissing a visible tip in a panel. Make the narrow product decision to allow the notification over the **ordinary centered phone menus** (Pause, Settings, Bag, Almanac, Calendar) as well as the unblocked world, not over full-screen/transactional story, travel, dialogue, shop, shipping, sleep, market confirmation, or morning summary. Dialogue deliberately uses Tab to cycle gift focus. These masked surfaces must retain normal Tab/focus behavior; do not silently dismiss a hidden prompt. This intentionally supersedes the old Settings mask expectation only; shop and other blocking-mask regressions remain. Keep the current top-right tip position and centered 560 px phone. The 1920×1080 logical canvas and existing 480 px tip leave a gap; verify their actual laid-out rectangles do not overlap in all locales. No repositioning work is planned.

- Register a named `dismiss_tutorial` action bound to unmodified Tab in project.godot. Use action checks, not a raw keycode in production. Handle the initial press in OnboardingOverlay._input before GUI focus traversal; only when TutorialCard is actually visible in tree, tutorial preference enabled, intro not visible, current prompt nonempty. Use `event.is_action_pressed(&"dismiss_tutorial", false, true)` (no echo, exact match including modifiers); consume the matched event before dismissal. With no visible tip, do not consume Tab or change focus/progress. Existing Enter/Space/Esc prologue handler stays unchanged.
- Use one shared dismissal method for button and action, keyed by _current_prompt_id. Preserve transient _dismissed and existing ContentRules.next_tutorial_prompt behavior; never write tutorial completion to GameSession or persistent preferences. A held Tab cannot dismiss subsequent tips. No duplicate or resurrected dismissed prompt after snapshot/locale refresh or modal close.
- Keep GameHud the modal/presentation owner and OnboardingOverlay the prompt renderer. Replace the two direct TutorialCard.visible writes with an idempotent `set_suppressed(bool)` on the overlay, enforced by the same render/settings visibility path (settings, intro and prompt gates). Maintain exactly one allow-list in GameHud next to the primary modal registration (the five existing panel references, not another registry); read it only in `_reconcile_modal_presentation()`. Any unlisted visible primary modal suppresses tips by default. `_open_modal()` does not currently reconcile on main: explicitly call reconcile **after** the existing visibility loop and **before** `modal_state_changed.emit()`. Keep the existing close/render/settings reconciliation and make sure re-render never bypasses suppression. Preserve HUD chrome, exclusivity and `has_blocking_modal()` independently of tip visibility. The tip never blocks world input itself.
- In `_build_modals()`, after ordinary panels are added and before adding `_travel_overlay`, move `_onboarding_overlay` to the last existing child (`_root.move_child(_onboarding_overlay, _root.get_child_count() - 1)`). Travel is then appended and the toast is built afterwards: overlay above phone menus, below travel and toast, with existing mouse filters and no reparenting. Moving the whole overlay also moves the prologue's full-screen STOP-filter OpeningPanel; check actual click-to-advance/Skip and Enter/Esc behavior, and assert sibling order. Do not use the travel node's current index after appending it as a target for the earlier overlay (the removal shifts that index).
- A mouse click on the visible dismiss row must still work over menus; clicks elsewhere on the notification are nonblocking. Tab does not open/close the menu, change settings, advance the clock, trigger world actions, or dismiss the prologue. Turning Tips off hides it; turning on recomputes the current eligible prompt.

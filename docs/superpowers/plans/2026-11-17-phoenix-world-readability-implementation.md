## Preflight: what already exists

- `scripts/world/world_shell.gd` currently reads `player.current_target_cell()` for the farming preview, E prompt/dispatch and again for five modal callbacks (buy, watering-can upgrade, deposit, sleep, market confirm). All five callbacks need the same **resolved** contract cell as E, or a panel can open but its domain command can still be rejected.
- `scripts/player/player_controller.gd` owns the raw diamond highlight and `WorldMath.target_cell()`; `Space` / hold farming must continue to use the raw cell, not the E resolver.
- `WorldContract` / `TownContract` hold interactable cells, collision footprints and camera bounds. `FarmMap` and `TownMap` build collision from those constants; `GameSession` must not change.
- `TownContract.backdrop_cells()` and `TownMap._ready()` already calculate/paint non-playable camera coverage. Farm needs the same behavior, not another map size or camera.
- Farm/town scenes already have Y-sorted `Entities` children with visual `Sprite2D` nodes. Player is inserted as first `Entities` child after each map swap; a prop at equal Y is drawn in front.
- GUT regression helpers `tests/integration/test_gameplay_shell.gd:_place_target()` and e2e `_stand_at_target()` currently teleport to an exact-cell stand location. Keep those existing checks and **add reachable, collision-stop proximity scenarios**, rather than loosening interaction reach to satisfy teleports. `tests/e2e/gameplay_day_one_test.gd` already drives input on the running game through godot-e2e.
- Localization uses `assets/i18n/strings.csv` columns `keys,zh_TW,ja`; the English text *is* the key.

For **every physically reachable side**, cover its **two** positive-dot screen facings, both negative-dot facings, a **physically unobstructed** empty-cell backoff and nearest-candidate/tie determinism. Include the House door slice, farm truck/bin, and town truck/shop/market/all villagers. Specifically pin the Seed Shop/Sato-san +x-side case and Market/Hana neighbor collision, where turning away from one prop or backing off may legally face a different one. Never teleport a probe inside an existing collider. Drive real collision-stop poses, not just remote teleports.

Pin the anti-through-wall example: Seed Shop +x-side contact (~5px from shop) while facing DOWN has a raw target of Sato-san's cell, but must **not** resolve Sato-san (roughly 26px away); when no valid inward-facing region exists at that pose, return empty. Add **synchronous** `_set_target()` → `world._process(0.0)` transitions from E to farming to idle and from a `null` raw target to a valid physical E hint, checking that no stale/hidden highlight remains. Require wrong-facing E to **avoid the tested object**; require full refusal from a position clear of other interactables.
5. From physical fallback contacts, open the real shop/upgrade, shipping, sleep and Day-14 market-confirmation panels and **submit** their existing actions. ## Task 2 — Contract-defined interaction regions and one E resolver

**Files:** `scripts/world/world_contract.gd`, `scripts/world/town_contract.gd`, `scripts/world/world_math.gd`, `scripts/world/world_shell.gd`, `assets/i18n/strings.csv`, `tests/integration/test_gameplay_shell.gd`, `tests/unit/test_localisation.gd`; GUT/GdUnit tests above. **No `PlayerController` modifications needed.**

1. Add `WorldContract.interact_regions()` and `TownContract.interact_regions()` mapping canonical contract cells to already-defined **collision footprint** rects; derive `WorldContract.BED_CELL`'s reachable door region as `HOUSE_FOOTPRINT.intersection(Rect2(BED_CELL, Vector2.ONE))` (currently `Rect2(12, 7, 1, 0.25)`). Pair town villager cells with existing `VILLAGER_FOOTPRINTS`. Do not duplicate these constants in `WorldShell`.
2. Add a tiny `WorldMath.closest_contact(world_ground_position, collision_rect)` helper implemented using existing `footprint_to_polygon` and `Geometry2D.get_closest_point_to_segment` for its four projected edges. The fallback's initial reach is **14 projected/world px**, not 32; require `facing_direction.dot(contact_direction) > 0` with **no angle cone** and no zero-distance special path. Tune only to satisfy both valid into-edge facings at real collision stops while rejecting one empty cell gap.
3. `WorldShell._resolve_interactable()` evaluates **physical regions first**: find all contacts within `<= 14` projected px, return the nearest one satisfying positive facing dot (stable contract ordering on ties). If **any** physical region is within reach but none passes the facing rule, return empty; **do not** fall back to a farther raw-cell target. Only when **zero** regions are nearby, try existing `_interactable(player.current_target_cell())` as the exact-cell fixture/legacy input path. This prevents Seed Shop contact facing DOWN from falsely resolving Sato-san's raw cell. Return `{cell, label, action}` or empty by reusing `_interactable(cell)`; do not duplicate its switch or add a registry.
4. Route `_process()` E hints, `_prompt_anchor(resolved.cell)`, `interact()` and **all five** modal submit handlers through this same resolver. Re-resolve the frozen pose on submit (input gate already freezes the Player); **do not** hardcode `TownContract.SHOP_CELL` etc. into session calls. Session guard, cost and save behavior remain authoritative.
5. **At the start of** `WorldShell._process(delta)`, call `player._update_target()` so the raw diamond is restored on **every** frame, including GUT tests using `_set_target()` followed immediately by `_process(0.0)` without a physics tick. (Call `_update_occluder_fade(delta)` near the top too—Task 3.) For an E hint, overwrite the existing `player.target_highlight.points = WorldMath.cell_diamond(resolved.cell)` **and** set `player.target_highlight.visible = true` in the E branch; the raw target may have been `null`/hidden. The shell's frame paint is last before normal render, with no highlight override state. Farming/blocked/idle branches preserve the freshly restored Space raw diamond, including early returns. E still independently resolves Shipping at the bin/Space overlap. `enter_map()` keeps its pre-physics initial highlight.
6. Replace `Bed,床,ベッド` at existing `assets/i18n/strings.csv` row ~327 with **one** `Go to bed,去睡覺,寝る` entry. The E hint in `_interactable()` uses the new English key. Update the **three** existing `[E] Bed` assertions in `tests/integration/test_gameplay_shell.gd` (~lines **2418, 4021, 4977**) to `[E] Go to bed`; add `Go to bed` zh_TW/ja translation expectations in `tests/unit/test_localisation.gd` (existing locale checks near lines **103–118**). Verify en/zh_TW/ja; do not append a duplicate key.

## Task 3 — Shared per-sprite foreground fade, no cached nodes

**Files:** `scenes/world/farm_map.tscn`, `scenes/world/town_map.tscn`, `scripts/world/world_shell.gd`, `tests/integration/test_gameplay_shell.gd`.

1. Opt relevant static Y-sorted `Entities` roots into one `player_occluder` Godot group: farm house/bin/fences/truck and genuinely tall props; town buildings/truck and occluding scenery. Keep crops, villagers, harvest FX/pops and player out, so this fade does not interfere with existing alpha effects.
2. Call `_update_occluder_fade(delta)` **before any** world-input/modal/hold/farming-preview early returns at the **top** of `WorldShell._process(delta)`, so props update while the player faces a farm tile or a modal is open. The helper queries `get_tree().get_nodes_in_group("player_occluder")` **per frame**, restricted to active map roots. Compute transformed bounds of **`prop.get_node("Sprite2D") as Sprite2D`** versus `player.player_sprite`'s drawn bounds, leaving the sibling `Shadow` unchanged. Fade only if bounds overlap and `prop.global_position.y >= player.global_position.y` (Player is child index 0 for exact Y ties).
3. Use one constant `FADE_ALPHA` around 0.45–0.50, but let **each prop's own** `Sprite2D.self_modulate.a` track opacity via `move_toward` toward FADE_ALPHA or 1.0. No shared mutable alpha, new shader, per-prop tuning table, tween registry, stored node references or map-replacement cleanup.
4. Test farm house/bin/fence/truck and town building fade/restoration from **reachable** poses, including with a farming-preview/blocked input gate; pass **positive** `delta` (e.g. `world._process(1.0)`) when testing `move_toward` because `_process(0.0)` cannot advance opacity. **Do not assume front-face contact means opaque:** `House`, `Truck`, `Station`, `SeedShop`, `Cafe` and `Market` roots use a *southern-tip* `footprint_ground_anchor()`, so even front-contact pose midpoints may be in front of the player in Y-sort and correctly fade. For opaque-restoration screenshots/assertions, move physically **south of the prop's root Y anchor** or clear of the drawn sprite rectangle. `Shipping` uses a different **cell-centre** anchor; verify that it can fade on -x/-y contacts and stay opaque at +x/+y contacts. Also assert a non-overlapping prop, stable Y tie, opacity 1 on new map after travel, Shadow unchanged, and crop/harvest FX not faded.

**GREEN checkpoint:** Only covering foreground props fade in both maps, with no flicker or leaked state across map replacement.

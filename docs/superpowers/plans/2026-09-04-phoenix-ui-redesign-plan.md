# Phoenix UI Redesign and Visual Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild all player-facing Phoenix UI to the approved mock-derived design, add only the missing UI-facing mechanisms, and finish with deterministic visual-regression coverage for all 14 approved states without turning the task into a world-art rewrite.

**Architecture:** `GameSession` remains the only mutable gameplay authority; `GameRules`, `VillagerRules`, and `ContentRules` own policy/content. `GameHud` stays the `WorldShell` signal boundary and owns a small modal registry plus ordered global-Esc close table; substantial surfaces are extracted from the current HUD builders into focused scene/script pairs. Human design parity is approved against mock-derived 1280x720 references; automated regression compares Godot production captures against Godot production goldens.

**Tech Stack:** Godot 4.7.1 standard non-.NET, GDScript, existing GUT clean verifier, GdUnit4/godot-e2e, semantic PNG UI assets, bundled open-licensed FontFiles, Godot-native capture/diff tooling.

**Spec:** `docs/superpowers/specs/2026-09-04-phoenix-ui-redesign-design.md`

**Reference Contract:** `docs/superpowers/specs/2026-09-04-phoenix-ui-reference-contract.md`

## Global Constraints

- Logical viewport stays exactly `640x360`.
- Browser/mock images are human design references, never strict machine goldens.
- Machine goldens are 640x360 production captures generated by the same Godot harness used by CI.
- A state gets a production golden only after manual side-by-side approval against its mock-derived design reference.
- Use bundled Open Sans / JetBrains Mono `FontFile`s; no `SystemFont`, no mock-webfont extraction.
- Production assets use semantic names. Test plates/design references/goldens live under `tests/visual/`, not `assets/`.
- Raw reference/golden/plate PNGs are loaded with `Image.load_from_file(ProjectSettings.globalize_path(...))`; their directories contain `.gdignore`.
- No Theme resource, modal framework, component library, DI, second session holder, Shop/Shipping base class, or save migration.
- `GameHud` owns `_primary_modals` and `_esc_close_order`; panel scripts do not duplicate general Esc/exclusivity.
- `DialoguePanel` retains the existing close-friend Esc swallow as the one exception.
- `GameRules` owns earliest-ready policy; `VillagerRules` owns favourite-villager inversion.
- Settings are Music `0..10`, Sound `0..10`, Window `1x/2x/3x/4x/FULL`, Tutorial Cards `ON/OFF`.
- `O` is handled only while Pause/Controls is open.
- Future random weather never appears in Calendar.
- Keep one implementation PR: `docs/ui-redesign-visual-parity` / PR #13. Task commits are review checkpoints inside that PR.

## Risks

### Browser-vs-Godot rasterization

Mitigation: mock/browser references are human design oracles only; machine regression uses Godot-generated goldens.

### Cross-platform GL drift

Mitigation: prove/calibrate state 01 before other panels land; hard ceilings `12/255` channel and `0.002` mismatch prevent weakening the gate.

### Golden blessing risk

Mitigation: `--update-goldens` is manual-only and used after side-by-side mock approval; CI cannot invoke it.

### Modal-list drift

Mitigation: Task 5 introduces one `_primary_modals` registry and ordered Esc close table before the new surfaces register.

### Fixture/environment drift

Mitigation: fixtures are frozen in the reference contract; all game states validate before restore; Settings displays `SaveRepository.DEFAULT_PATH`, not environment overrides.

### Single-PR review size

Mitigation: keep one PR as requested, with one reviewable commit per task/checkpoint and final draft acceptance spanning the whole UI slice.
